# NetZapret

Диспетчер трафика для Windows. Для каждого приложения, домена или подсети решает,
куда пустить трафик: **через десинк** (Zapret / winws2), **через VPN** (sing-box)
или **напрямую** — и запускает оба движка под одним присмотром.

Заменяет собой связку Zapret + VPN-клиент и делает то, чего не делает ни одна
из них по отдельности: **применяет VPN точечно, не ломая десинк для всего остального.**

## Установка

1. Скачать архив со страницы [релизов](https://github.com/RixyPow/netzapret/releases/latest).
2. Распаковать куда угодно.
3. Запустить `netzapret.exe`.

Больше ничего ставить не нужно — ни .NET, ни sing-box, ни Zapret: всё внутри.
Права администратора программа запросит сама, без них не поднимутся ни туннель,
ни драйвер перехвата пакетов.

Понадобится только **ссылка на подписку VPN** — любой провайдер, поддерживаются
VLESS, Trojan, Hysteria2 и Shadowsocks. Вставляется в меню, пункт «VPN».

Ссылка равносильна паролю: по ней выдаётся весь список серверов с учётными
данными. Хранится рядом с программой в `config\netzapret.json` и никуда
не отправляется.

### Первый запуск

```
  1. Режим работы .......... выборочно
  2. Пресет Zapret ......... Universal V6
  3. VPN ................... не задана, авто (по задержке)
  4. Автозапуск ............ выключен
  5. Маршруты приложений ... нет своих

  6. Собрать конфиг
  7. Запустить (конфиг соберётся сам)
  8. Обзор состояния
  9. Журнал супервизора
```

Пункт **VPN** → вставить ссылку → там же проверить серверы → пункт **Запустить**.
Конфиг соберётся сам.

Если что-то не так — **Обзор состояния** покажет, что найдено и что готово
к работе, а **Журнал супервизора** — чем занимались движки.

## Зачем это нужно

Десинк и VPN плохо уживаются. Под поднятым туннелем трафик выходит переоткрытым
сокетом sing-box, а WinDivert рассчитывает увидеть исходный поток приложения —
и рецепты Zapret с поддельными пакетами перестают работать. Замер это подтвердил:
голый `multidisorder` (YouTube) и `send + syndata` (Discord) туннель переживают,
а `fake` (Google, Claude) — нет.

Очевидное решение — вывести десинк-трафик из туннеля через `route_exclude_address` —
не годится: в пресете Universal V6 из двадцати секций с `fake` четырнадцать
сопоставляются по доменам, а поле принимает только адреса. Прикрыло бы пять из двадцати.

Здесь сделано наоборот: **fakeip выдаётся только доменам с правилом `proxy`**, и в
туннель заводится лишь то, что этими адресами адресовано. Десинк-трафик туннеля
не касается вовсе. Подробности — [docs/coexistence.md](docs/coexistence.md).

## Режимы работы

| Режим | Что происходит |
| --- | --- |
| Выключено | Весь трафик напрямую, ни один движок не запускается |
| Только десинк | Работает winws2, туннель не поднимается вовсе |
| **Выборочно** | По умолчанию десинк, VPN включается правилами. Основной режим |
| Всё через VPN | Всё в туннель, кроме выведенного напрямую |
| Всё через VPN без исключений | Буквально всё, включая российские сервисы |

Российские сервисы через зарубежный адрес не работают: банки и госуслуги требуют
подтверждений, часть отказывает наотрез. Поэтому «всё через VPN» сохраняет правила
`direct`, а режим без исключений вынесен отдельно — он нужен для сравнения, когда
надо убедиться, что дело не в правилах.

Локальные сети и loopback остаются прямыми в любом режиме.

## Правила

Два слоя. **Базовый** `config/rules.yaml` — выверенный набор, то, что заблокировано
наверняка; ведётся вместе с программой. **Пользовательский** `config/rules.user.yaml` —
ваш выбор поверх него, его ведёт меню. Разделение затем и сделано, чтобы обновление
не затирало ваши правки.

```yaml
mode: selective

capture:
  - lists/ipset-telegram.txt      # приложения, ходящие по голым адресам

rules:
  - match: ipset
    value: lists/ipset-ru.txt
    mode: direct                   # российские — только напрямую

  - match: domain
    value: "*.rutracker.org"
    mode: proxy

  - match: process
    value: "somegame.exe"
    mode: direct

default:
  mode: desync                     # всё остальное чинит десинк
```

`match`: `process` | `domain` | `ip` | `ipset` | `hostlist`.
`mode`: `direct` | `proxy` | `desync`.

`hostlist` ссылается на доменный список Zapret целиком — так устроен вид
по сервисам: «голос Discord через VPN» это `lists/discord-media.txt`, а не
горсть выписанных строк, которые устареют молча.

## Сервисы

Пункт меню **Сервисы и маршруты** показывает то, о чём человек думает —
Discord, YouTube, Telegram, — а внутри сервиса его части:

```
  Discord
  1. Голос                    VPN         1 дом.   <- ваш выбор
     голосовые серверы; ломается отдельно от переписки
  2. Текст и вход             десинк     43 дом.
  3. Картинки и вложения      десинк      3 дом.
```

Каждую часть можно направить отдельно. Ради этого разделение и сделано:
у Discord голос ломается иначе, чем переписка, и лечится иначе.

Состав сервисов взят из списков Zapret и разбора пресета Universal V6, где
части уже разделены. Сервис — способ показа и редактирования, а не отдельная
сущность: выбор разворачивается в обычное правило `hostlist`, а домен,
направленный вручную, узнаётся в своём сервисе.

Приоритет по типу: сперва все `process`, затем `domain`, затем адресные, затем
`default`. Порядок строк внутри одного типа сохраняется. Маска `*.example.com`
покрывает и сам `example.com`.

Секция `capture` нужна приложениям, которые ходят по адресам без обращения к DNS —
Telegram один из них. Перехват решается по адресу назначения, и без этих подсетей
их трафик просто не дойдёт до туннеля, сколько бы правил на них ни стояло.

Куда пойдёт конкретная цель, можно спросить не запуская движков:

```bash
netzapret where rutracker.org
```

```
  rutracker.org  →  VPN

  Опознано как: домен
  Основание:    domain rutracker.org ~ *.rutracker.org
  Правило:      #0 domain:*.rutracker.org -> proxy
```

## Проверка блокировок

Пункт меню **Проверка блокировок** отвечает на вопрос, ради которого программу
и открывают: почему не работает и что с этим делать. Она открывает настоящие
соединения и смотрит не на то, что не вышло, а **как** не вышло — каждый
способ вмешательства лечится своим.

```
                              TCP   1.2   1.3   HTTP  ДАННЫЕ  вердикт
  twitter.com                 ок    RST   RST   ок    —      DPI по TLS
  steamcommunity.com          ок    ок    ок    ок    нет    обрыв после рукопожатия
  rutor.info               чз ок    нет   нет   ок    —      DPI по TLS
  tr.rbxcdn.com               нет   —     —     —     —      оборванный CNAME
```

Столбец **ДАННЫЕ** важнее прочих. Рукопожатие само по себе ничего не доказывает:
`steamcommunity.com` проходил все остальные проверки и при этом не открывался —
приходило 14381 байт, и поток замирал. Поэтому проверка качает данные и следит
за молчанием, а не за объёмом: у страниц он разный.

Метка **«чз»** — цель уже идёт через туннель, и её строка описывает туннель,
а не сеть. TCP там всегда «ок»: соединение принимает sing-box, ещё не
дозвонившись до хоста.

Отчёт открывается тем, чем он снят — режим, пресет, сервер, резолвер. Без этого
два прогона не сравнить: проверка снимает не свойства сети, а поведение сети
под конкретной настройкой.

```bash
netzapret blockcheck --full
```

`--quick` — по имени с каждой части, `--full` — по два, `--service <имя>` —
один сервис целиком. Пробы идут разом, **Esc** прерывает и показывает набранное.

Проверять надо при остановленных движках: с включённым обходом видно сеть уже
вылеченной. Программа предупреждает и в таком случае не советует спускаться
на ступень ниже — доступное сейчас может быть доступно как раз благодаря обходу.

### Чего проверка не решает

Часть отказов приходит не от оператора, и маршрутом они не лечатся.

**Сайт отказывает по стране.** ChatGPT, Spotify и другие сами закрываются
от российских адресов. Связь при этом исправна: рукопожатие проходит, страница
приходит — с кодом 403 и надписью «недоступно в вашей стране». Десинк влияет
на то, как соединение выглядит для DPI, а решение принимает сайт, уже разобрав
запрос. Помогает только выход в другой стране.

**У имени нет адреса.** `tr.rbxcdn.com`, по которому Roblox отдаёт превью, —
CNAME на имя без записи A. Соединяться не с чем. Такое лечится подстановкой
адреса — см. ниже.

## Свои адреса и списки

**`config\addresses.yaml`** — адреса для имён, у которых своего нет:

```yaml
addresses:
  tr.rbxcdn.com: 18.165.140.59
```

Отвечает наш резолвер, системный `hosts` не трогается. Разница существенная:
правки в hosts требуют администратора, переживают удаление программы и видны
всем приложениям, а это снимается вместе с конфигом.

Адреса сетей доставки не вечны. Если перестало работать — возьмите свежий
с живого узла того же CDN и замените строку.

**`config\lists\`** — доменные списки для того, чего нет у Zapret. Оттуда
Valheim, Pinterest, TMDB и раздача превью Roblox: в его списках они
не значатся, а значит десинк их не касается вовсе.

## Что мешает перехвату

Три вещи обходят маршрутизацию по домену молча, и все три уже встречались.

**DNS over HTTPS.** Windows 11 сама поднимает запрос до DoH, и он уходит по TCP/443
мимо перехвата: домен резолвится по-настоящему, fakeip не выдаётся, трафик идёт
напрямую под блокировку. NetZapret закрывает DoH к системным резолверам внутри
туннеля, и Windows возвращается на обычный UDP.

**Файл hosts.** Он бьёт любой резолв, включая наш: имя ищется в нём **до** DNS,
и прибитый там домен fakeip не получит никогда. Совпадение точное, без зон —
строка `example.com` не покрывает `www.example.com`, отсюда списки на сотни
строк. После правки нужен `ipconfig /flushdns`: Windows держит записи в своём
кэше с огромным сроком жизни.

Такие адреса находятся при сборке конфига и заводятся в туннель принудительно —
трафик доходит до sing-box, тот опознаёт домен по SNI и применяет обычное
правило. Проверка блокировок показывает прибитые имена отдельным разделом
и советов по ним не даёт: пока запись на месте, маршрут ничего не решает.

Сам файл мы не правим. Его ведёт не только человек: редактор hosts есть
в Zapret GUI, и часть записей может быть нужна для обхода. Для своих
подстановок у нас `config\addresses.yaml`.

**IPv6.** Без адреса IPv6 у TUN `auto_route` не ставит ни одного маршрута IPv6,
и резолвер провайдера остаётся снаружи, отвечая настоящими адресами в обход fakeip.
Перехват при этом выглядит исправным — обход идёт по второму протоколу.

### Если оператор перекрыл шифрованный DNS

С августа 2026 российские операторы начали ограничивать DoH и DoT. Наш апстрим —
тоже DoH, и его отказ выглядит как «перестало открываться вообще всё»: имена
не разрешаются, и на неисправность маршрутов это не походит ничем. Поэтому обзор
состояния проверяет резолвер отдельно и называет причину.

Лечение — разрешать имена внутри туннеля, где оператор их не видит:

```json
"DnsThroughTunnel": true
```

По умолчанию выключено намеренно. Включённое, оно ставит разрешение имён
в зависимость от туннеля: пока тот не поднялся, не открывается ничего, включая
то, что прекрасно работало на десинке. Включать, когда прямой DoH уже отказал,
а не заранее.

## Антивирусы

Сборка даёт 3 срабатывания из 66 на VirusTotal, и все три — на **WinDivert**,
драйвер перехвата пакетов. Помечается как `RiskTool` и `PUA`, Kaspersky пишет
прямо: `Not-a-virus`. Без него обход DPI невозможен, и та же картина у Zapret
и GoodbyeDPI.

Программа не подписана сертификатом издателя, поэтому Windows покажет SmartScreen.
Из поставляемых файлов подписаны двое: `wintun.dll` — WireGuard LLC, и драйвер
`Monkey64.sys` — сторонней организацией, не связанной с проектом WinDivert.
Подробности в [docs/THIRD-PARTY.md](docs/THIRD-PARTY.md).

## Командная строка

Меню закрывает обычную работу, но всё доступно и напрямую:

```bash
netzapret doctor                    # что найдено, что готово к работе
netzapret blockcheck                # что закрыто в этой сети и чем это лечится
netzapret where <цель>              # куда пойдёт домен, программа или адрес
netzapret rules                     # правила в порядке вычисления
netzapret dns                       # резолверы: кто отвечает и с какой задержкой
netzapret probe --sub <ссылка>      # какие серверы живы и с какой задержкой
netzapret sub --sub <ссылка>        # подписка: квота, срок, список серверов
netzapret config --sub <ссылка>     # собрать конфиг sing-box
netzapret preset                    # пресеты Zapret и их секции
netzapret start / stop / status     # супервизор
netzapret autostart install         # запуск при входе в систему
netzapret clean                     # убрать рантайм-артефакты
```

Права администратора нужны только `start` и `autostart`. Проверка серверов
их не требует: поднимается локальный инбаунд, TUN не создаётся, маршруты
не трогаются.

`blockcheck` стоит запускать при остановленных движках — иначе он покажет
сеть уже с обходом, а не такой, какая она есть. Программа об этом
предупреждает, но сама ничего не останавливает.

## Сборка из исходников

Нужна, только если вы собираетесь менять код — для работы достаточно архива
из релизов.

**1. .NET SDK 8 или новее.**

```bash
winget install Microsoft.DotNet.SDK.8
```

**2. sing-box** — для VPN. Скачать сборку `windows-amd64` с
[github.com/SagerNet/sing-box/releases](https://github.com/SagerNet/sing-box/releases)
и распаковать в `tools/` целиком, вместе с `wintun.dll` — без неё не поднимется TUN.
Нужна версия не ниже 1.11; проверялось на 1.13.19.

**3. Zapret 2** — для десинка. Ставится отдельно; NetZapret находит установку сам
и читает её пресеты, hostlist'ы и ipset'ы как есть.

Без sing-box работает всё, кроме VPN. Без Zapret — всё, кроме десинка.
Что именно нашлось, показывает `netzapret doctor`.

Дальше:

```bash
dotnet build
```

```bash
dotnet test
```

```bash
build.cmd
```

`build.cmd` останавливает движки, раскладывает результат в `build\` и складывает
туда же движки, так что собранная копия работает сама по себе. Запуск из `bin\`
ломал бы пересборку: MSBuild пишет в тот же каталог, где лежат загруженные сборки.
Что именно копируется и почему не через репозиторий — в [tools/README.md](tools/README.md).

Готовый архив и публикация релиза:

```bash
pack.cmd
```

```bash
release.cmd 0.1.0
```

## Устройство

| Модуль | Что делает |
| --- | --- |
| `NetZapret.Core` | Модель правил, режимы, движок сопоставления |
| `NetZapret.Subscriptions` | Разбор ссылок и подписок, квота и срок из заголовков |
| `NetZapret.Proxy` | Генерация конфига sing-box, проверка серверов |
| `NetZapret.Zapret` | Разбор пресетов winws2, сборка его командной строки |
| `NetZapret.Supervisor` | Запуск движков, слежение за живостью, перезапуск |
| `NetZapret.Cli` | Меню и команды |
| `NetZapret.Etw` | Наблюдение за соединениями и DNS через ETW |
| `NetZapret.Wfp` | Наблюдение через WFP net-events, `--source wfp` |
| `NetZapret.Dns` | Статическая карта имён для отладки, `--hosts-map` |

Принуждение выполняет **route-движок sing-box**, а не собственный код. NetZapret
владеет правилами и их семантикой, sing-box — исполнением. Своего WFP-callout'а
в проекте нет: кастомная классификация и `ALE_CONNECT_REDIRECT` живут только
в kernel-mode драйвере, а тот требует WDK, EV-сертификата и attestation-подписи.

Оба движка работают под супервизором в Job Object с `KILL_ON_JOB_CLOSE`: осиротевший
sing-box удерживает TUN-адаптер, осиротевший winws2 — WinDivert, и следующий запуск
падает неочевидно.

### Почему наблюдение на ETW, а не на WFP

`watch` изначально подписывался на net-events WFP. На Windows 11 26200 события
`FWPM_NET_EVENT_TYPE_CLASSIFY_ALLOW` не приходят вообще: сбор включён, ключевое
слово принято, подкатегория аудита включена — а событий нет, и записей 5156
в журнале безопасности тоже нет. Доходят только `CLASSIFY_DROP`, по которым
диспетчер не построить.

Реализация WFP осталась рабочей и доступна через `--source wfp`: смещения структур
проверены на живых событиях, и она понадобится для защиты от утечек.

## Известные ограничения

* серверы **VLESS + REALITY** у некоторых провайдеров не подключаются — ограничение
  sing-box, поддержка Xray вторым движком запланирована;
* обновление ручное: скачать архив и распаковать поверх;
* установщика нет, только архив;
* интерфейс текстовый;
* проверка блокировок не пробует пути, которыми цель ещё не ходит — вывод
  «нужен VPN» сделан по тому, что не работает напрямую, а не по тому, что
  заработает через туннель.

коммерческих продуктов. Единственное требование: сохранить уведомление
об авторстве.

Движки, входящие в сборку, остаются на своих условиях: sing-box — GPL v3,
Zapret — MIT, WinDivert и Cygwin — LGPL, `wintun.dll` — проприетарная
лицензия WireGuard LLC. Они запускаются отдельными процессами и на лицензию
NetZapret не влияют. Разбор — в [docs/THIRD-PARTY.md](docs/THIRD-PARTY.md).
