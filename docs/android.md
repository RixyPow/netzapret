# NetZapret на Android

Исследование 26.10.2026: что из программы переносится на телефон, что
заменяется, чего не будет, и в каком порядке делать. Решений владельца
по нему ещё нет — вопросы в конце. Учтено, что следом могут быть iPhone,
macOS и Linux, но делается сейчас Android.

## Коротко

- **Туннель переносится почти целиком.** sing-box на Android — родная
  вещь (libbox внутри приложения, так у всех клиентов), наш форк сам
  выпускает сборку под Android. Подписки, серверы, пулы, сторож, правила,
  пины, проверка блокировок, замер скорости — логика на C#, и три четверти
  библиотек собираются без Windows уже сегодня.
- **Десинк в нынешнем виде не переносится.** winws2 подделывает пакеты
  через драйвер; на телефоне без root подделать пакет нельзя — можно только
  резать поток своим сокетом (как ByeDPI). seqovl, badseq, tcp_ts, autottl,
  syndata и lua без root недоступны, tcp_md5 — только если позволит ядро,
  а в V12 Lite на них стоит почти всё.
  С root — тот же движок (nfqws2) и **те же пресеты**.
- **Многое на телефоне проще, чем на Windows**: маршрут по приложению —
  родной (на Windows он «на переработке»), пины — правилами DNS движка
  без hosts и прав администратора, «Наблюдение» — из самого движка с именами
  приложений.
- **Новые беды, которых на Windows нет**: один VPN на телефон (с Happ
  не вместе), российские приложения ищут VPN (методичка Минцифры от
  апреля 2026), частный DNS слепит правила по именам, прошивки убивают
  фоновую работу, на мобильной сети — белые списки по адресам, против
  которых десинк бессилен.
- **Предлагаемый путь**: .NET + Avalonia, libbox внутри, сначала
  «Туннель», десинк — после замера на телефоне владельца. До решений —
  замер и проба (раздел «План»).

## Что на телефоне устроено иначе

1. **Пакет не подделать без root.** Приложению доступны только свои
   сокеты: TTL (`IP_TTL`), срочные данные (`MSG_OOB`), разбиение записью,
   `TCP_MD5SIG`, если ядро даёт. Сырых сокетов (`CAP_NET_RAW`) у него нет.
   bol-van на вопрос о zapret без root (zapret#1809, 22.10.2025): «Нет,
   вам нужен byedpi».
2. **Весь трафик идёт через VPN-службу.** Приложение получает TUN и само
   открывает соединения наружу. Поэтому «полный перехват» на телефоне —
   обычное дело: десинк живёт внутри того же пути, а не рядом, как
   winws2. Решение владельца 20.10 «полного перехвата в „Гибриде“ не
   будет никогда» стоит на устройстве Windows (winws2 видит только то,
   что идёт мимо TUN) и на телефон не переносится — сюда его надо
   принимать заново.
3. **Один VPN на телефон.** Включил NetZapret — Happ выключился, и наоборот.
4. **Владелец соединения известен движку**: `getConnectionOwnerUid`
   (Android 10+) отдаёт приложение, у sing-box есть правила `package_name`.
   Исключать приложения из VPN целиком умеет и сама служба (allowed или
   disallowed — смешивать нельзя).
5. **hosts без root не править.** Пины уходят в DNS движка: компилятор
   уже умеет отдавать имени свой адрес резолвером `hosts` (`AddressOverrides`,
   так чинится `tr.rbxcdn.com`). Права администратора и «Проверить
   актуальные адреса» с подменой файла не нужны вовсе.
6. **Частный DNS (Настройки → Частный DNS).** По коду AOSP он действует
   и на сеть VPN: в строгом режиме имена уходят по DoT на 853 сквозь TUN,
   перехват DNS, fakeip и правила по имени слепнут. Люди ставят его
   именно ради обходов. Надо видеть и предупреждать. Chrome сам уходит
   на свой DoH, если DNS сети — известный публичный (8.8.8.8): DNS туннеля
   объявляется частным адресом — у нас так и есть (`TunDnsAddress`, 172.19.0.2).
7. **Российские приложения ищут VPN.** Методичка Минцифры, разосланная
   06.04.2026 (ntc.party 23842): признаки `TRANSPORT_VPN`, интерфейсы
   tun0, маршруты, MTU, **открытые порты на 127.0.0.1** (SOCKS 1080 и др.).
   С 15–16.04 Госуслуги, банки, Ozon, WB, ВК ограничивали людей с VPN.
   RKS Global (16.04): все 30 проверенных приложений VPN видят, 13 из них —
   **даже исключённые из туннеля** (перебирают интерфейсы). Сканер
   RKNHardering достаёт из Clash API sing-box на 9090 адреса серверов.
   Отсюда правила для телефона: **ни одного слушателя на 127.0.0.1 без
   нужды** (Clash API — только через внутренний канал libbox, вход
   health-in — не портом), российские приложения — вне туннеля по
   умолчанию, и честно писать, что от перебора интерфейсов это не спасает.
8. **Фоновая работа.** VPN-служба — с типом `systemExempted` (Android 14+;
   `dataSync` на Android 15+ ограничен шестью часами в сутки). Xiaomi,
   Huawei и другие всё равно убивают — нужен экран «как не дать убить»
   (dontkillmyapp.com) и проверка в «Диагностике».
9. **Белые списки на мобильной сети** (2026): сперва отбор по адресам
   и сетям (63 тыс. адресов), потом по имени; UDP режется, внешний DNS
   молчит. **Десинк тут не помогает.** Помогает вход VPN из белой сети
   (российский VPS в Яндекс Облаке, VK Cloud — «ОБС» у SecureWay). Ценное
   для NetZapret: узнать режим белых списков почерком (`Signatures`)
   и сказать «переключитесь на сервер ОБС» — или переключить самому.
## Что в коде — замер 26.10

Все шесть библиотек (`Core`, `Proxy`, `Subscriptions`, `Zapret`,
`Supervisor`, `Etw`) собраны под `net8.0` вместо `net8.0-windows`
(копия в скрэтчпаде): **ошибок ноль**. Анализатор совместимости (CA1416)
нашёл 29 вызовов API только для Windows в семи файлах — реестр
(`BrowserDns`, `OtherBypass`, `WindowsIpv6`, `DeviceIdentity`, `WinDivertDriver`)
и `WindowsIdentity` (`AutostartTask`, `Doctor`). Чего анализатор не видит:
`DllImport` в семи файлах (`IconCache`, `PinnedIcon`, `RunningPrograms`,
`FileLockers`, `ProcessImageResolver`, `DnsCache`, `ProcessJob`), запуск
`sc.exe`, `schtasks`, `ipconfig`, `powershell`, привязка сокета к адаптеру
ключом `IP_UNICAST_IF` (`DnsSurvey`, `RouterDnsConnection`), путь к hosts.

«Собирается» — ещё не «работает». Счёт по строкам:

| | строк | что это |
|---|---:|---|
| Библиотеки всего | 49 916 | |
| Только Windows | ~7 900 | hosts (2 370), ETW, WinDivert, обновление подменой файлов, значки и ярлыки, автозапуск планировщиком, «Диагностика» Windows, чтение журналов Discord и Roblox, вывод серверов из перехвата winws2 |
| Переделать шов | ~4 000 | надзор на `Process` (`SupervisedService` 2 047, `ProcessSupervisor`, `SingBoxRunner`), строка winws2 (`WinwsCommandLine` 663), `Doctor` |
| Логика без Windows | ~38 000 | правила и маршруты, списки, каталог, компилятор конфига sing-box, подписки и разбор ключей, пулы, пины, проверка блокировок, почерки поломок, DNS, замер скорости, отчёт |
| Тесты библиотек | 31 247 | идут вместе с логикой |
| Окно (WPF) | 37 495 + 11 214 XAML | не переносится |

Что из этого следует:

- **Логика переносится, если приложение на .NET.** Три четверти библиотек —
  код, которому всё равно, Windows под ним или нет; на Kotlin его пришлось бы
  написать заново вместе с тестами.
- **Надзор придётся разделить** на «как движок запущен» (процесс на
  компьютере, библиотека внутри приложения на телефоне) и «как за ним
  следить» (сторож, пулы, лестница DNS, замеры через Clash API). Второе
  переносится, первое — своё у каждой системы.
- **Окно не переносится ни при каком выборе.** WPF есть только на Windows,
  моделей представления в нём нет — логика разделов живёт в коде окон
  (`RoutesView` 3 264 строки, `VpnView` 3 174, `StatusView` 2 314).
  Что в окне не вид, а дело, — вынести в библиотеки: `SupervisorHost` (718),
  `TunnelConfig` (571), `EngineControl` (315), `SubscriptionBook` (322),
  `SubscriptionRecheck`, `StartupSweep` — около 2 000 строк. Это нужно
  и самой Windows (правило «логика — в библиотеках») и делается до телефона.
- **Файлы библиотеки ищут от текущей папки** (`config\`, `runtime\` — 45 мест).
  На телефоне это папка файлов приложения; поставка (`config\`, списки,
  каталог) распаковывается туда при первом запуске.

## Десинк

### Без root

Что из рецептов zapret2 повторяется своим сокетом (руководство zapret2,
раздел tpws у bol-van, код byedpi):

| Приём | Без root |
|---|---|
| multisplit, tcpseg | да — отдельными `send()`; Linux может склеить мелкие куски |
| multidisorder | только «через TTL»: первый кусок с TTL=1, ядро повторяет его через ~200 мс |
| fake с низким TTL | только трюком byedpi: `vmsplice`/`splice`, подделка уходит, страница перезаписывается настоящими байтами |
| tcp_md5 | `TCP_MD5SIG`, если ядро позволит (byedpi: на Android может быть выключен) |
| badsum, badseq, tcp_ts, datanoack | нет |
| autottl | нет — сокет не видит TTL входящих; только постоянный TTL |
| seqovl, ipfrag, wssize, lua | нет |
| hostfakesplit, fakedsplit | только приближение (fake + split) |
| syndata, send | нет (TFO — отчасти, без cookie ядро данные в SYN не шлёт) |
| oob, tlsrec | да |
| подделка QUIC (`fake` по UDP) | да — лишние датаграммы с низким TTL, без autottl |

В V12 Lite (по умолчанию) рецепты — `hostfakesplit:…:tcp_ts:tcp_md5`,
`multidisorder:…:seqovl=1`, `send`+`syndata`, QUIC `fake` с `ip_autottl`.
Ни один не переносится как есть. **Пресеты V12 на телефон без root не
едут — нужен свой каталог рецептов в другой, бедной модели.** Секции
по именам и спискам при этом переносятся: «имя из списка → рецепт»
у ByeDPI есть (`--hosts`, `--ipset`, группы с `--auto`).

Чем резать — четыре кандидата:

| | Что | Плюсы | Минусы |
|---|---|---|---|
| `tls_fragment` / `tls_record_fragment` sing-box (с 1.12) | рвёт приветствие по меткам имени, в случайном месте | уже в движке, ничего встраивать, работает и на iPhone | сам sing-box пишет «не для настоящей цензуры»; против ТСПУ 2026 никто не мерил; tlsrec у bol-van в РФ обычно ломает TLS 1.2 |
| ByeDPI (C, MIT) | split, disorder, oob, tlsrec, **fake через vmsplice**, udp-fake, группы и автоподбор | самый богатый без root; ByeByeDPI (GPL-3, 1.8.2 от 02.10.2026) держит его через JNI | SOCKS-прокси — значит, слушатель на 127.0.0.1 (без пароля у ByeByeDPI — прямой признак из методички); перезапуск только в отдельном процессе; выпусков больше года нет |
| Outline SDK (Go, Apache-2.0, бета) | split, tlsfrag, disorder через TTL, `x/smart` — сам подбирает DNS и разрез | Go, как sing-box: встраивается исходящим типом — lantern-box (Apache-2.0) так и сделал, `"type": "outline"`; без слушателя; годится для iPhone | подделок нет вовсе |
| Свой приём в форке движка | fake через `vmsplice` в Go (`unix.Vmsplice`) | всё в одном Go | форк форка — поддерживать нам |

**Какой брать — решает замер, не чтение.** Отчёты с мест не обнадёживают:
ByeByeDPI на мобильной сети «не открывает ничего, кроме ютуба» —
заморозка на 16 КБ (ntc.party 26426, 19.10.2026); перебор SNI на мобильной
сети быстро блокируют; сайты на зарубежных CDN «простой» fake не открыл
(9075, январь 2026). Домашний Wi-Fi — тот же провайдер, что у компьютера,
и там картина может быть лучше.

Предпочтение при равных замерах — **внутри Go-движка** (`tls_fragment`,
затем приёмы Outline): без слушателя на 127.0.0.1, без JNI к C, и тот же
код потом работает на iPhone и macOS.

### С root

nfqws2 с lua на Android работает — bol-van собирает его в CI (NDK, API 21,
4 ABI, LuaJIT), на нём стоят модули nzapret (MIT, 4.0.0 от 18.10.2026)
и magisk-zapret2 (AGPL, 2.3.8 от 25.10.2026). Перехват — iptables NFQUEUE.
Значит, **с root — те же пресеты, lua, списки и каталог рецептов**, меняется
только строка перехвата (`--qnum` вместо `--wf-*`) — ровно то же понадобится
Linux. Вдобавок sing-box с root умеет `auto_redirect` (nftables) без
VPN-службы: **признака VPN у телефона нет вовсе**. Аудитория маленькая,
но это лучший режим из возможных — и он же половина пути к Linux.

### Через Shizuku — не сейчас

DesyncDroyd (ntc.party 25826, 07.09.2026) гонит настоящий nfqws2 без root:
TUN → nfqws2 → тестовый TAP из `TestNetworkManager` как раздаваемый
Ethernet. Нужен Shizuku (запуск заново после каждой перезагрузки),
скрытые API, сам автор называет приём хрупким, проверен только IPv4/TCP,
лицензии нет. Следить, не брать.

## Язык и интерфейс

Три пути, и решает не вкус, а то, сколько кода писать дважды.

| | .NET + Avalonia | Kotlin + Compose | .NET + MAUI |
|---|---|---|---|
| Логика (~38 тыс. строк и 31 тыс. тестов) | берётся как есть | пишется заново | берётся как есть |
| Интерфейс | пишется заново (WPF не переносится) | пишется заново | пишется заново |
| Тот же интерфейс потом на iPhone, macOS, Linux, Windows | да | iPhone и компьютер — Compose Multiplatform, Windows остаётся на C# | без Linux |
| Чем держится на Android | VpnHood — VPN целиком на C#, интерфейс на Avalonia 12 (сверено 26.10 по репозиторию) | все клиенты обхода: SFA, v2rayNG, NekoBox, приложение tg-ws-proxy-rs | — |
| Размер APK | ~20 МБ своего + движок (VpnHood arm64 — 21,3 МБ) | меньше | как Avalonia |

**Предлагаю .NET + Avalonia.** Логика и тесты — общие с Windows, правка
в правилах или подписках чинится сразу на обеих системах. Avalonia же
пробуется сейчас и для компьютера (`probe/avalonia-home`, 26.10): если окно
Windows когда-нибудь переедет на неё, интерфейс тоже станет один на все
системы. Цена: Avalonia на телефоне моложе Compose, и родного вида Android
(поведение «назад», клавиатура, отступы под вырез экрана) придётся добиваться
руками. Kotlin — путь надёжнее для одного Android, но тогда два кода
навсегда, и каждая находка из CLAUDE.md переписывается второй раз.

Важно: **интерфейс телефона — не копия окна.** Узкий экран, пальцы,
одна рука: «Главная» с большой кнопкой и строкой состояния, VPN, маршруты
по приложениям и папкам, проверка блокировок. Наблюдение, hosts, темы
с видео, редактор тем — нет или позже.

Среда выполнения: .NET 10 (LTS до 14.11.2028, на Android — Mono) или
.NET 11 (выходит в ноябре 2026, RC2 уже есть). В .NET 11 CoreCLR — среда
по умолчанию на Android и iOS, Mono остаётся запасной (devblogs.microsoft.com,
13.05.2026); на iPhone CoreCLR вдвое легче в памяти (VpnHood: ~23 МБ против
~42). Наименьший Android у .NET 11 — 7.0 (API 24). Какую брать на телефон —
решит проба. Windows уходит с .NET 8 в любом случае — см. «Попутно».

## Как встроить движки

**sing-box — библиотекой внутри приложения (libbox).** Так делают все:
SFA (официальный клиент), v2rayNG, NekoBox, Hiddify, Clash Meta. Готовый
консольный sing-box, как на Windows, не годится: VPN-служба отдаёт TUN
дескриптором, а у входа `tun` нет ключа «принять готовый дескриптор»;
отдельный процесс возможен только со своей обёрткой (см. «Лицензия»). **Наш форк (shtorm-7
sing-box-extended 1.14.3-extended-2.7.3) сам выпускает сборку SFA**:
39,9 МБ под arm64 — значит, libbox из форка собирается под Android, XHTTP
и прочие его добавки будут на телефоне те же.

Как C# говорит с libbox — два способа, ни у одного нет готового примера
на .NET:
- AAR (gomobile) + библиотека привязок .NET для Android — штатный путь
  .NET для Java-библиотек; интерфейсы libbox (`PlatformInterface`: открыть
  TUN, защитить сокет, найти владельца соединения) пишутся на C#.
- Своя обёртка на C (`-buildmode=c-shared`) + P/Invoke — больше своего
  кода, меньше прослоек.

Непроверенное, что решается только пробой: .NET и Go в одном процессе
(обратные вызовы из потоков Go в управляемый код; Go требует, чтобы чужие
обработчики сигналов стояли с `SA_ONSTACK`).

**Лицензия — решение владельца.** sing-box — GPL-3.0-or-later. На Windows
он лежит рядом отдельной программой, и наш MIT это не задевает. По GPL FAQ
модули в одном адресном пространстве — «почти наверняка» одна программа:
**с libbox внутри APK распространяется на условиях GPL-3.0** — с исходниками
всего (они открыты и так). Файлы нашего кода при этом остаются MIT: MIT
с GPL совместим. Два пути:
- **APK под GPL-3.0, libbox внутри** — как у всех; проще и быстрее.
- **MIT, sing-box отдельным процессом** — файл `lib*.so` из папки библиотек
  (запуск из своей папки Android 10+ запрещает), своя обёртка на Go над
  libbox и канал для передачи TUN, `protect()` и поиска владельца соединения
  (последний вправе звать только процесс приложения). Образец —
  shadowsocks-android (`libtun2socks.so`, дескриптор через Unix-сокет).
  Плюс: падение движка не роняет интерфейс. Минусы: свой код на Go, вызов
  через процесс на каждое соединение, Android 12+ убивает лишние процессы.

Не юридический совет. Прочие куски с GPL уживаются: ByeDPI и
hev-socks5-tunnel — MIT, Outline SDK — Apache-2.0, tg-ws-proxy-rs — MIT.
Название sing-box в имени приложения использовать нельзя (оговорка лицензии).
**libbox.aar форк отдельно не публикует** — собирать самим (`make lib_android`).

**tg-ws-proxy-rs** у автора уже есть под Android (2.5.8 от 25.10, APK
5 МБ, cargo-ndk и своя прослойка JNI) — переносится без риска.

**winws2 на телефон не едет вовсе** — см. «Десинк».

## Распространение

| Путь | Что с ним |
|---|---|
| GitHub + Obtainium | открыт; главный путь, как у v2rayNG |
| IzzyOnDroid | принимает .NET (VpnHood там есть) |
| F-Droid (основной) | закрыт для .NET: ни одного приложения .NET не принято — SDK не собирается из исходников |
| Google Play | VPN-приложениям нужна учётная запись **организации** с номером D-U-N-S и декларация VpnService; запрещено обновлять себя мимо Play и докачивать `.so` — то есть обновлять движки отдельно. Требования РКН Google в основном не выполняет (из 212 названных приложений недоступны стали 6, март 2025), но Play — работа на месяцы |
| RuStore | для обхода блокировок не годится |

**Проверка разработчиков Android — главный риск 2027 года.**
С 30.09.2026 сертифицированные телефоны в Бразилии, Индонезии, Сингапуре
и Таиланде не ставят приложения непроверенных разработчиков из магазинов;
**в 2027 году — по всему миру и для APK с сайта**. Сверено по FAQ Google
26.10:
- проверка — $25 и личность автора, связанная с пакетом и ключом подписи;
- APK через ADB ставится без проверки;
- «продвинутый путь» для опытных: режим разработчика, сутки ожидания,
  подтверждение отпечатком; **без него обновления непроверенного
  приложения не ставятся**;
- проверка не работает на устройствах «в странах под всеобъемлющими
  санкциями». Россию Google не называет ни разу; американский перечень
  таких стран — Иран, Куба, КНДР, оккупированные области Украины. Российские
  издания пишут, что телефоны в России будут исключены, Минцифры 24.09
  «оценивает риски». Не решено. Люди вне России (Беларусь, Казахстан,
  уехавшие) попадут под проверку в любом случае.

Проверка связывает настоящее имя автора с инструментом обхода — решение
только владельца. Ключ подписи APK заводится один раз и навсегда:
потерян — пакет не обновить ни у кого.

**Обновление изнутри** — `REQUEST_INSTALL_PACKAGES` и PackageInstaller;
человек один раз разрешает «установку из неизвестных источников».
Окно обновления с чейнджлогом по разделам переносится — разделы меню
у телефона будут свои.

## Потом: iPhone, macOS, Linux

Что решить сейчас, чтобы потом не переделывать:

- **iPhone.** VPN там — расширение Network Extension с потолком памяти
  50 МБ на весь процесс (Apple DTS, без изменений в iOS 26). .NET внутри
  расширения работает (VpnHood: CoreCLR ~23 МБ в покое), но вместе с Go
  и правилами на 37 тысяч имён не влезет — оценка, не замер. Значит,
  **расширение — только libbox, а конфиг собирает приложение на C#**
  и отдаёт готовым JSON. Ровно так устроена и Windows: окно собирает
  конфиг, движок его исполняет. Отсюда правило для Android тоже: всё,
  что судит и решает, — в C#, движок получает готовый конфиг и
  отвечает на команды. App Store: VPN — только от организации, российская
  витрина фактически закрыта (Apple выполняет требования РКН: в 2025-м
  удалила по ним 1 213 приложений всех видов, в марте 2026-го — VPN
  v2RayTun, V2Box, Streisand и одну версию Happ); остаётся выпуск в других странах и чужая учётная
  запись Apple у человека. Боковой установки для России нет.
- **macOS.** Avalonia на компьютере + sing-box отдельной программой (как
  у v2rayN — C#, Avalonia, движки процессами). Вне Mac App Store
  расширение VPN — только системное, с нотаризацией и платной учётной
  записью Apple. zapret2 на macOS bol-van не обещает — десинк там как
  на телефоне без root, на уровне сокетов.
- **Linux — проще всех для десинка.** zapret2 родом с Linux: nfqws2
  берёт **те же пресеты и lua**, что winws2, меняется только перехват
  (`--qnum` и правила nftables вместо `--wf-*`). sing-box — программой,
  как на Windows. Нужны права root или `CAP_NET_ADMIN`, служба systemd.
  Интерфейс — та же Avalonia.

## Устройство приложения

```
Приложение (C#, .NET, Avalonia)
├─ логика — библиотеки src/, общие с Windows
│    правила, подписки, пины → компилятор → готовый JSON sing-box
├─ слой Android (C#)
│    VpnService (systemExempted), PlatformInterface libbox:
│    открыть TUN, protect(), владелец соединения; уведомление,
│    плитка в шторке, always-on, обновление APK, физическая сеть
└─ движок — libbox из форка extended (Go)
     TUN, маршруты, VPN, DNS, пины, сокетный десинк
     связь с C# — команды libbox внутри процесса, не Clash API на порту
```

Правило то же, что на Windows и что понадобится на iPhone: **всё, что судит
и решает, — в C#; движок получает готовый конфиг и отвечает на команды.**

Швы, которые надо прорезать в библиотеках (польза и Windows, и Linux):

| Шов | Windows | Android |
|---|---|---|
| Как движок запущен | процесс (`SupervisedService`) | libbox в процессе |
| Как им управлять | Clash API на 127.0.0.1 с секретом | команды libbox |
| Сокет мимо туннеля | `IP_UNICAST_IF` на физический адаптер | `protect()` / `Network.bindSocket` |
| Десинк | строка winws2 | рецепты сокетного движка; с root — строка nfqws2 |
| Вход TUN в конфиге | `interface_name`, `route_address`, `strict_route: false` | `include_package`/`exclude_package`, без имени адаптера |
| Номер устройства для панели | отпечаток `MachineGuid` | отпечаток `ANDROID_ID` (постоянен для ключа подписи) |
| Папка данных | корень установки | папка файлов приложения |

Репозиторий — **тот же**: библиотеки общие, приложение Android — своей
папкой (`android/`), CI собирает APK рядом с архивом Windows. Библиотеки —
сразу под две цели (`net8.0-windows` и обычную), чтобы Windows не
сломалась ни на день.

## Разделы программы на телефоне

| Раздел | На телефоне |
|---|---|
| Главная | своя: кнопка, режим, сервер, состояние; уведомление с «Остановить» и плитка в шторке |
| VPN | логика целиком: подписки (телефон для панели — ещё одно устройство в лимите HWID), серверы, сторож, пулы, WARP; ключи — вставкой и камерой |
| Десинк | без root — свой движок и свои рецепты; с root — те же пресеты |
| Маршруты | да; маршрут по приложению — родной, а не «на переработке» |
| TG Proxy | позже; проще вести Telegram через VPN по приложению — прокси на 127.0.0.1 виден сканерам |
| Проверка блокировок | логика переносится; путь «через туннель» — без SOCKS на порту |
| Замер скорости | да |
| DNS | да; плюс частный DNS телефона; DNS роутера — позже |
| Файл hosts | нет — пины правилами DNS движка |
| Наблюдение | да, и лучше Windows: соединения из движка с именем приложения |
| Диагностика | своя: частный DNS, другой VPN, батарея и прошивка, always-on, белые списки |
| Оформление | позже, без видео |
| Обновление | APK с GitHub, изнутри |

## План

### Этап 0 — пробы и замер, до решений

1. **Замер десинка на телефоне владельца — без нашего кода.** ByeByeDPI
   1.8.2 (его подбор стратегий по своему списку) и SFA из форка extended
   (готовый APK) с маршрутом direct + `tls_fragment`, затем
   `tls_record_fragment`. Домашний Wi-Fi и мобильная сеть отдельно. Имена —
   из проверки блокировок 24.10 (168, на компьютере закрыты 15) плюс
   закрытые без обхода. Мерить на телефоне — curl из Termux по списку
   (Termux идёт через VPN-службу). Отвечает на вопрос, нужен ли «Гибрид»
   на телефоне вообще и с каким движком.
2. **Проба приложения** — как `probe/avalonia-home`, вне git. .NET +
   Avalonia 12 + libbox из форка (AAR привязкой), VpnService на C#, конфиг
   нашим компилятором из подписки владельца, одна кнопка и проверка
   блокировок кодом `BlockCheck`. Мерить: размер APK, запуск, память,
   батарею за час с погасшим экраном, падения на стыке Go и .NET, скорость
   против SFA на том же сервере. Не взлетело (стык нестабилен, батарея
   заметно хуже SFA) — пересмотреть язык.
3. **Решения владельца** — вопросы ниже.

### Этап 1 — «Туннель» на телефоне

Сперва в этом репозитории, на пользу Windows: вынести дело из окна
в библиотеки, прорезать швы, библиотеки под две цели. Потом приложение:
подписки, серверы, сторож, WARP; маршруты VPN/напрямую, российские зоны,
приложения в VPN и мимо (российские — мимо по умолчанию); пины через DNS
движка; «Главная», уведомление, плитка, always-on; «Диагностика» телефона;
обновление APK; отчёт файлом.

Это уже полезно само: клиент VPN с нашими правилами, пинами и проверками —
то, чего у Happ нет.

### Этап 2 — десинк без root

По итогам замера: движок, свой каталог рецептов, маршрут «десинк»
в «Маршрутах», проверка блокировок на телефоне, почерк «белые списки» →
«переключитесь на ОБС».

### Этап 3 — root

nfqws2 с нашими пресетами и lua, sing-box через `auto_redirect` без
VPN-службы. Та же работа открывает Linux.

### Этап 4 — остальное

TG Proxy, «Наблюдение» по приложениям, оформление.

### Не будет

Десинк пакетами без root, hosts, ETW, «Прятать VPN» в нынешнем виде
(на телефоне это исключение приложений из туннеля), Shizuku — пока.

## Попутно, не о телефоне

**Поддержка .NET 8 кончается 10.11.2026** (и .NET 9 — тоже; сверено
по dotnet.microsoft.com 26.10). После неё — ни одной заплатки
безопасности для программы, которая работает с правами администратора
и ставит драйвер. .NET 10 — LTS до 14.11.2028. Переезд нужен Windows
сам по себе, а для телефона это и так первый шаг.

## Вопросы владельцу

1. **Нужен ли телефон без десинка?** Первая версия — «Туннель» с нашими
   правилами, подписками, пинами и проверками. Или без десинка телефон
   не нужен вовсе?
2. **Лицензия APK:** GPL-3.0 с libbox внутри (проще) или MIT с движком
   отдельным процессом (сложнее)?
3. **Замер этапа 0:** какой телефон (модель, версия Android), какой
   оператор мобильной связи; можно ли поставить ByeByeDPI, SFA форка
   и Termux?
4. **Root** — есть ли у тебя или у твоих людей; нужен ли этап 3?
5. **Распространение:** только GitHub (+ Obtainium, IzzyOnDroid) или ещё
   Google Play (учётная запись организации, D-U-N-S)? Проверка
   разработчика в 2027 году — регистрироваться ли под своим именем?
6. **Язык** — .NET + Avalonia после пробы или сразу Kotlin?
7. **Русские приложения вне туннеля по умолчанию** — каким списком
   (банки, Госуслуги, маркетплейсы, ВК, Яндекс) и можно ли честно
   сказать людям, что 13 из 30 видят VPN и так?
